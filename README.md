# Steering Through the Trees: Physical Lie Vector Field Evasion of Tree Ensembles in Network Intrusion Detection

[![Python 3.13](https://img.shields.io/badge/python-3.13-blue.svg)](https://www.python.org/)
[![CUDA Accelerated](https://img.shields.io/badge/CUDA-XGBoost%20CUDA-green.svg)](https://developer.nvidia.com/cuda-toolkit)
[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](LICENSE)
[![Target Journal](https://img.shields.io/badge/Journal-Elsevier%20Information%20Sciences-orange.svg)](https://www.sciencedirect.com/journal/information-sciences)

Reference implementation of **Flow-Field Evasion (FFE)**, a constraint-preserving evasion attack against gradient-boosted tree ensembles in flow-based network intrusion detection, and of a **certified monotone-gate defense**. The attacks are red teaming: they estimate the worst case that a schema-constrained adversary with score access can reach, and the defense turns part of that estimate into a guarantee for the flows it flags.

* **FFE-v1** (`src/attacks/flow_field_evasion.py`): four packet-level actions (temporal dilation, payload padding, chaff injection, TCP window morphing) as commuting generators of a Lie cone on the flow manifold, steered by score probes, with optional tree-split boundary snapping. Kept unchanged as the reference baseline.
* **FFE-v2** (`src/attacks/ffe_v2.py`): adds a re-segmentation generator (same payload in more, smaller packets; an optional TCP-option-padding generator exists but is not in the frozen configuration), a multi-scale geometric probe ladder per generator, data-driven window targets drawn from the attacker's benign sample, log-odds progress, cheapest-crossing selection with bisection refinement, and optional threshold snapping. The headline variant is **score-only**.
* **Defense V2** (`src/defenses/`): OR-fusion of a certified monotone gate (hides window, rates and mean length; non-decreasing in forward packets, forward bytes, duration and header bytes) with an augmentation-hardened free classifier. MPS and LGAT are kept as baselines.

## 1. What the benchmark measures

All results are computed on the **complete, deduplicated** CSE-CIC-IDS2018, CIC-IDS2017 and UNSW-NB15 captures (no sampling), mapped to a 12-feature flow schema.

| Dataset | Raw rows | Valid | Exact duplicates removed | Kept | Attacks | Train / Test |
| :--- | ---: | ---: | ---: | ---: | ---: | :--- |
| CSE-CIC-IDS2018 | 8,284,254 | 8,153,708 | 3,185,319 | 4,968,389 | 594,809 | 3,477,872 / 993,679 |
| CIC-IDS2017 | 2,099,971 | 2,085,851 | 426,982 | 1,658,869 | 396,403 | 1,161,208 / 331,774 |
| UNSW-NB15 | 257,673 | 215,689 | 92,181 | 123,508 | 55,559 | 86,456 / 24,703 |

The distributed CSE-CIC-IDS2018 files are capped at 1,048,575 rows each; the UNSW-NB15 files are the official training/testing partition. Records with identical features and label are collapsed before the stratified 70/10/20 split; records with identical features but different labels are kept (149,526 / 22 / 1,040). The split is random, so near-duplicate flows can fall on both sides and accuracies are optimistic.

## 2. Main results (Real ASR = evades **and** schema-feasible, in %)

Every number is regenerated by `experiments/summarize_results.py` from `results/*.json`. Protocol: FFE-v2 was designed and tuned on cohorts of the 10% validation split, the configuration was frozen (`results/ffev2_config.json`) and evaluated once on the 1,000-flow test cohorts (CatBoost: the flows it detects, N = 1000 / 997 / 983).

| Target and corpus | FFE-v1 | White-box control | FFE-v2 (score-only) | FFE-v2 + snapping |
| :--- | :---: | :---: | :---: | :---: |
| XGBoost, CSE-CIC-IDS2018 | 99.5 | 99.5 | 99.5 | 99.5 |
| XGBoost, CIC-IDS2017 | 99.2 | 100.0 | 100.0 | 100.0 |
| XGBoost, UNSW-NB15 | 57.6 | 90.2 | 98.3 | 98.5 |
| LightGBM, CSE-CIC-IDS2018 | 99.5 | 99.5 | 99.5 | 99.5 |
| LightGBM, CIC-IDS2017 | 35.1 | 36.6 | 96.0 | 96.0 |
| LightGBM, UNSW-NB15 | 62.4 | 88.1 | 96.7 | 99.2 |
| CatBoost, CSE-CIC-IDS2018 | 59.3 | 99.5 | 99.5 | 99.5 |
| CatBoost, CIC-IDS2017 | 34.8 | 36.4 | 36.4 | 36.4 |
| CatBoost, UNSW-NB15 | 70.1 | 56.8 | 97.5 | 97.7 |

On XGBoost the seven earlier baselines reach at most 88.5 / 89.5 / 42.0 (CAPGD 88.5 / 89.5 / 21.1; all 21 comparisons with FFE-v2 are significant after Holm correction, largest adjusted p = 8e-28).

What this does and does not show:

* FFE-v2 is at least as successful as our greedy projected white-box control (our own implementation; LT-Attack and Cascioli et al. were not run) and as FFE-v1 in all nine cells, significantly above the control in four (UNSW-NB15 x 3, CIC-IDS2017 LightGBM) and above FFE-v1 in seven (exact McNemar, no correction). Five-seed means (5 seeds XGBoost, 3 LightGBM/CatBoost, no tuning on these runs): UNSW-NB15 XGBoost 97.7 vs FFE-v1 58.3, control 86.0, CAPGD 31.5; FFE-v2 was never below FFE-v1, the control or CAPGD in any seed.
* **Evidence caveats.** The single test evaluation is not a clean hold-out: the FFE-v1 failures that motivated FFE-v2 were first seen on the same test cohorts, re-segmentation was motivated by the control's moves on the same corpora, and the window pool uses the attacker's benign training sample; validation tuning queries are not counted. The five-seed study (retrained models, fresh cohorts, no tuning) is the cleaner confirmation (3 seeds for LightGBM/CatBoost; pooled tests treat flows as independent). All corpora are pre-projected onto the schema manifold before training (byte totals above 1500 x packets, durations above 110 s and UDP header sizes are clamped). "Schema-feasible" is relative to `verify_physical_feasibility`, which does not check the header-plus-payload gap; the five generators are not linearly independent (`seg` = `chaff` - L0 x `pad`).
* **CatBoost on CIC-IDS2017 (36.4%) is a ceiling, not an attack win**: the DDoS/DoS decision rests on attacker-immutable features (backward packets, backward bytes, destination port: 77% of gain importance); a multi-start search found no crossing for 37 sampled DDoS and 40 DoS flows (3 of 80 sampled failed flows reachable, all port scans), which cannot prove unreachability.
* FFE-v2 is **score-only**; the snapping variant also reads thresholds and adds up to 2.5 points (UNSW-NB15 LightGBM) and at most 0.2 elsewhere. The control reads the trees and uses 2 queries; for LightGBM and CatBoost it is our generic greedy variant, not LT-Attack.
* **Costs are real.** FFE-v2 uses about 30-40 queries (v1: 14.6-93.7; control 2; CAPGD 3-16; 109 on the unreachable CIC-IDS2017 CatBoost flows). On UNSW-NB15 its operational cost on the flows both evade is higher than v1's (paired medians 6.7 vs 5.8, 14.6 vs 7.5, 29.1 vs 9.8); a re-segmented packet is priced like a chaff packet.
* **Packet replay (synthetic traces only)**: with chaff carrying the booked bytes (or empty chaff compensated by padding) 100% of FFE-v2's evasions survive on all corpora, including 118 UNSW-NB15 flows that use re-segmentation; if empty chaff drops the booked bytes, UNSW-NB15 retains 69.2% (replayed ASR 68.0%). No real network stack was involved, and the schema holds backward packets fixed, which is optimistic for segmentation.
* LightGBM on CIC-IDS2017 was 35.1% for FFE-v1 because its fixed window target (64,240 B) lies in an empty region of the training data (`results/diagnosis_lightgbm.md`); data-driven windows give 96.0%.

### Defense (`results/defense_v2_report.md`; Real ASR on 1,000-flow cohorts, one seed)

On every corpus and library the fused V2 keeps validation accuracy, F1 and recall from falling by more than 0.5 point and, against FFE-v1 (M = 5, 20), CAPGD and an adaptive white-box threshold-crossing attacker, reduces Real ASR to at most 8.8% on CSE-CIC-IDS2018 (white-box: 8.8 / 7.9 / 8.1 for CatBoost / LightGBM / XGBoost, versus 99.5-100 undefended and for LGAT), at most 0.7% on CIC-IDS2017, and 1.0-32% on UNSW-NB15 (a relaxed tier V2-R reaches 0.5-4.7% for about 2 accuracy points). The certificate: any flow the gate flags stays flagged under every schema-feasible transformation (Real ASR is computed on the flows still detected, so the stand-alone gate's 0.0% is not complete coverage), **conditional on the port, protocol and backward features staying fixed** (the gate reads them without being monotone in them) and on the schema threat model; a lower-footprint variant of the same attack flow is not covered. Not certified: the roughly 8% of CSE-CIC-IDS2018 flows the gate does not flag (still evadable), the UNSW-NB15 residual (LGAT is better than V2 against FFE-v1 for LightGBM), and the accuracy cost of the stand-alone gate (about 0.7 accuracy / 3.8 F1 / 5.5 recall points on CSE-CIC-IDS2018, 1.6-1.8 accuracy points on UNSW-NB15 XGBoost/LightGBM). **FFE-v2 was not evaluated against the hardened models**, random forests and the manipulation-signature detector were not evaluated, and there is one seed.

│   ├── run_full_benchmark.py    # FFE-v1 + baselines -> results/full_<dataset>.json
│   ├── diagnose_ffev2.py, tune_ffev2.py   # validation-split diagnosis and tuning of FFE-v2
│   ├── run_ffev2.py, run_ffev2_replay.py, run_seeds_ffev2.py, report_ffev2.py   # frozen test run, replay, seeds

│   ├── run_whitebox.py, run_ablations.py, run_transferability.py, run_defenses.py  # FFE-v1 era studies

## 4. Reproduction

Environment used: Python 3.13, PyTorch 2.6.0+cu124, XGBoost 3.4.1, LightGBM 4.7.0, CatBoost 1.2.10, scikit-learn 1.8.0, NVIDIA RTX 5000 Ada (16 GB). See `requirements.txt`. Import `xgboost`/`lightgbm` before `torch` (the reverse order segfaults on this setup).

```bash
git clone https://github.com/vinhqdang/adversarial_ids.git && cd adversarial_ids
pip install -r requirements.txt

# 1. download the raw captures (about 4 GB) and build the deduplicated corpora
python -c "from src.datasets.full_data import download_raw, build_full_dataset; \
[download_raw(d) for d in ('cse2018','cic2017','unsw')]; [build_full_dataset(d) for d in ('cse2018','cic2017','unsw')]"

# 2. FFE-v1 benchmark, FFE-v2 (diagnose, tune on validation, frozen test run, seeds), defenses
python experiments/run_full_benchmark.py --datasets unsw cic2017 cse2018 --n-fast 1000 --n-slow 200
python experiments/diagnose_ffev2.py && python experiments/tune_ffev2.py
python experiments/run_ffev2.py && python experiments/run_ffev2_replay.py && python experiments/run_seeds_ffev2.py
python experiments/run_defenses_v2.py cse2018   # also cic2017, unsw

# 3. tables and statistics, then the paper
python experiments/summarize_results.py
bash paper/build.sh

python -m pytest -q tests
```

## 5. Responsible disclosure

This work was conducted on public academic intrusion datasets. Its aim is to expose structural weaknesses in ML detectors and to motivate invariant-aware robust training, not to facilitate attacks. No real network was attacked.
